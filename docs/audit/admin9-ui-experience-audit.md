## 1. 审计方法

本次审计读取当前源码、测试、架构文档、Phase 0 报告、六张 iOS 现状图和用户提供的两张注册页截图。没有修改或运行应用页面；Android 视觉、双端读屏和真机交互沿用原 Phase 0 的 Unknown 边界。

### 1.1 唯一主层级

| 层级 | 含义 |
| --- | --- |
| A | 产品范围或信息架构 |
| B | 页面模式与内容层级 |
| C | Design System、组件与 Token |
| D | 平台原生行为 |
| E | 无障碍、响应式或实现缺陷 |
| F | 暂无证据的主观假设 |

每条问题只能有一个主层级。涉及其他层级时仅记录影响，不把结构问题下沉给组件解决。

### 1.2 证据等级

| 等级 | 证据 |
| --- | --- |
| E1 | Apple、Android、Flutter 官方规范或明确建议 |
| E2 | Flutter 3.44.1 官方 API 默认行为或 SDK 源码 |
| E3 | 当前仓库源码、测试、设备命令和既有 Phase 0 报告 |
| E4 | 当前 SHA 截图或用户提供截图，只证明可见现象 |
| E5 | Admin9 产品/UX判断，必须由参考页面和验收任务验证 |

## 3. 审计记录

### UX-01 当前页面不是最终产品页面

- 主层级：A。
- 页面/状态/证据：全部页面；架构文档和当前无后端边界，E3。
- 观察：页面覆盖了骨架能力，但内容和层级主要为边界验证服务。
- 用户影响：若直接把现状包装成 Design System，会把临时目录和占位状态固化到派生项目。
- 行业惯例：先固定用户任务和页面模式，再抽取组件；Flutter adaptive guidance 也要求先识别共享数据和动态部位，E1/E5。
- Admin9 推荐：把当前页面定义为能力样本；先通过三张参考页面，再反推 v1.2 和组件。
- 严重度：P1。
- 处理阶段：现在处理，已进入产品体验基线。
- 影响：页面结构是；公共 API/Token 否，等待参考页面。
- 验收：所有后续文档不得把当前 Material 类型或现状间距称为获批规范。

### UX-02 个人中心混合了五种信息职责

- 主层级：A。
- 页面/状态/证据：我的/游客态，`account_page.dart`、`ios_02b_account.png`，E3/E4。
- 观察：身份摘要、登录注册、账号能力、设置、法务、关于和退出登录位于同一连续目录；游客仍看到退出登录入口。
- 用户影响：高频身份任务与低频说明竞争，用户难以判断哪些能力当前可用。
- 行业惯例：身份、账号、应用、法务和危险操作使用明确层级与隔离；危险项不与普通导航混排，E1/E5。
- Admin9 推荐：固定“身份摘要与主行动 → 账号能力 → 应用设置 → 法务/关于 → 危险操作”顺序；游客不显示可执行退出登录。
- 严重度：P1。
- 处理阶段：参考页面阶段处理。
- 影响：页面结构是；公共 API/Token 否。
- 验收：游客/登录两态低保真均能在一次首屏扫描中识别身份、主行动和可用能力；危险项独立且只在适用状态出现。

### UX-03 登录与注册的主次关系需要由身份状态决定

- 主层级：B。
- 页面/状态/证据：我的/游客态，两个等宽按钮，E3/E4。
- 观察：登录为实心、注册为描边，已有初步主次，但与身份说明、后续账号入口的整体节奏尚未验证。
- 用户影响：如果派生项目改变文案或增加入口，主行动可能失焦或重复。
- 行业惯例：一屏保留一个最可能行动的突出样式；相关选择使用样式而非尺寸区分，Apple HIG Buttons，E1。
- Admin9 推荐：游客态登录保持唯一主行动，注册保持次行动；注册页内部反向以“提交注册”为主、“返回登录”为次。
- 严重度：P2。
- 处理阶段：参考页面阶段处理。
- 影响：页面结构是；Token 待视觉校准；公共 API 否。
- 验收：两态参考图和完整任务中不存在重复登录/注册入口或两个等权重主按钮。

### UX-04 账号能力在游客态的可用性没有逐项说明

- 主层级：A。
- 页面/状态/证据：账号资料、安全、找回在游客态均可进入，E3。
- 观察：入口可达，但资料页、改密和注销最终都受“无会话/无服务”限制。
- 用户影响：用户进入后才知道不可用，产生无效导航。
- 行业惯例：入口状态应在执行前可预期，不把能力边界延迟到结果页，E5。
- Admin9 推荐：参考页面明确游客可用项仅为登录、注册、找回和公开应用信息；资料、安全、退出、注销在无真实会话时不作为可执行入口。
- 严重度：P1。
- 处理阶段：参考页面阶段处理。
- 影响：页面结构是；公共 API/Token 否。
- 验收：游客参考页的每个入口均可完成当前声明的任务，不存在必然落入“未接入”的日常入口。

### UX-05 注册页按钮与输入框比例只是密度信号

- 主层级：C。
- 页面/状态/证据：注册页；`registration_large.png` 与 `registration_standard.png`，E4。
- 观察：两图中字段、按钮、文字和间距随字号/密度变化；按钮视觉容器低于输入框，第一张整体更高。
- 用户影响：可能影响表单节奏和 iOS 观感，但截图没有实际 hit target、逻辑尺寸、系统字号和交互数据。
- 行业惯例：Flutter 3.44.1 Material 3 FilledButton 默认视觉最小 64x40，默认 tap target 48x48；Apple 要求 hit region 至少 44x44pt。视觉容器无需与输入框等高，E1/E2。
- Admin9 推荐：不规定等高，不升级为 P1；Phase 0C 在同一设备的标准/大字号样例中校准字段间距、主按钮视觉权重和命中区，控件采用 minimum constraints 与内容增长。
- 严重度：Unknown。
- 处理阶段：参考页面阶段处理。
- 影响：Token 可能；公共 API/页面结构否。
- 验收：记录逻辑尺寸、字号、字段/按钮视觉 bounds 与 hit bounds；两端无截字、误触或主行动失焦后，才能冻结度量。

### UX-06 六种认证流程共享结构，但任务差异没有形成模式契约

- 主层级：B。
- 页面/状态/证据：登录、注册、忘记、重置、改密、找回；`auth_form_page.dart`，E3。
- 观察：字段通过条件分支组合，次操作只覆盖部分流程；没有逐流程说明、凭据来源和完成后去向。
- 用户影响：派生项目接入后可能复用错误字段、自动填充语义或返回关系。
- 行业惯例：每屏完成一个认证任务，字段顺序、键盘 action、错误和完成去向与任务一致，E1/E5。
- Admin9 推荐：注册作为主样例、登录作为对照；其余四种流程在迁移前各自补产品契约，不从一个万能表单自动推导。
- 严重度：P2。
- 处理阶段：注册/登录在参考页面阶段，其余在迁移阶段。
- 影响：页面结构是；公共 API 否；输入组件能力可能。
- 验收：每个流程有字段表、前置条件、完成结果、返回关系和错误任务测试。

### UX-07 “服务未接入”边界是正确方向，但反馈位置尚未验收

- 主层级：A。
- 页面/状态/证据：所有认证提交、注销；ViewModel 与 `UnavailableNotice`，E3。
- 观察：本地校验通过后不创建会话，显示未接入状态。
- 用户影响：保证业务真实；若状态不靠近提交结果或不被读屏公告，用户仍可能误解。
- 行业惯例：成功只用于真实完成，未接入与错误分离，状态变化可被辅助技术感知，E1/E5。
- Admin9 推荐：保留边界；参考表单把未接入作为提交后的局部结果，不使用成功 tone，不清空用户输入。
- 严重度：P1。
- 处理阶段：现在固定语义，参考页面阶段校准位置，组件阶段实现公告。
- 影响：公共 API 可能涉及 Notice/Feedback；Token 否；页面结构是。
- 验收：提交后无会话、输入保留、状态可见且只公告一次，返回后状态符合契约。

### UX-08 资料页用禁用表单表达只读缺省信息

- 主层级：B。
- 页面/状态/证据：账号资料；两个 disabled TextFormField，E3。
- 观察：暂无昵称和账号被渲染为禁用输入框，而不是身份详情或空状态。
- 用户影响：看起来像可编辑但被禁止，无法解释是无会话、无数据还是无权限。
- 行业惯例：只读信息与可编辑表单使用不同模式，禁用只表示当前控件不可操作，E5。
- Admin9 推荐：游客不进入资料页；登录态参考真实数据决定只读摘要或编辑表单，不由通用 TextField 决定。
- 严重度：P2。
- 处理阶段：迁移阶段处理，等待真实派生需求。
- 影响：页面结构是；公共 API/Token 否。
- 验收：派生项目提供真实资料任务后再设计；当前不把 disabled 输入样式纳入公共组件验收。

### UX-09 账号注销的危险层级出现过早

- 主层级：A。
- 页面/状态/证据：账号安全、账号注销，E3。
- 观察：游客可进入注销页；危险入口虽为红色，但与修改密码、找回同列表相邻。
- 用户影响：无会话用户收到无效危险提示，真实用户也缺少与普通能力的空间隔离。
- 行业惯例：危险操作独立、明确后果，不能仅靠颜色；主按钮角色不得用于 destructive，E1。
- Admin9 推荐：个人中心参考页只在登录态显示独立危险区；账号安全页把日常安全能力与注销分隔，注销仍保留二次确认语义。
- 严重度：P1。
- 处理阶段：参考页面阶段固定层级，迁移阶段实现。
- 影响：页面结构是；公共 API 可能涉及 destructive action；Token 可能。
- 验收：游客无注销路径；登录态需要明确入口、后果页和确认任务，灰度下仍可识别危险语义。

### UX-10 设置页信息架构可保留，平台控件仍是 Material-only

- 主层级：D。
- 页面/状态/证据：设置；SegmentedButton、DropdownButton、SwitchListTile；iOS 深色图，E3/E4。
- 观察：外观与无障碍分组合理，但 iOS 使用 Material 控件、图标和列表密度。
- 用户影响：功能可用但不符合 iOS 熟悉的选择、开关和列表反馈。
- 行业惯例：品牌语义统一，平台选择器、switch、返回和列表行为原生；Flutter adaptive guidance 要考虑平台输入与能力，E1。
- Admin9 推荐：设置参考页固定同一信息架构和状态语义，Android/iOS 分别使用已批准的平台映射；即时生效，不增加保存按钮。
- 严重度：P1。
- 处理阶段：参考页面阶段设计，组件阶段实现。
- 影响：公共 API 是；Token 是；页面结构轻微。
- 验收：双端参考图、状态切换任务、Semantics 和真机读屏通过。

### UX-11 系统辅助设置与 App 设置尚未合并

- 主层级：E。
- 页面/状态/证据：全局；当前只读取 `AppAppearance`，字号上限 2.0，E3。
- 观察：高对比度、减少动态和字号主要由 App 偏好驱动；系统最大 Dynamic Type/非线性缩放没有证据。
- 用户影响：系统已开启辅助设置的用户可能仍得到普通对比度、动画或被截断的字号。
- 行业惯例：应用响应系统辅助设置，不能要求用户重复配置；Flutter/Apple accessibility guidance，E1。
- Admin9 推荐：v1.2 保留“系统要求与 App 偏好合并、移除 2.0 硬上限、保留非线性 TextScaler”的方向，但具体布局等参考页后再冻结。
- 严重度：P1。
- 处理阶段：组件/主题阶段处理；当前只记录基线。
- 影响：公共主题 API 是；Token 可能；页面结构可能。
- 验收：系统设置运行时变化、最大字号、无裁切、读屏和减少动态真机任务。

### UX-12 iOS 当前整体仍呈现 Material 结构

- 主层级：D。

- 行业惯例：Flutter 支持自动平台适配和 Cupertino 组件；导航、返回、选择和控件反馈应体现平台习惯，E1/E2。
- Admin9 推荐：Phase 0C 先做三张双端参考页，确认页面层级与平台差异，再反推组件；不先做全局“Cupertino 化”。
- 严重度：P1。
- 处理阶段：参考页面阶段设计，组件和迁移阶段实现。
- 影响：公共 API 是；Token 是；页面结构部分。
- 验收：双端参考页获批，随后用底层类型、手势和读屏证据验证平台映射。

### UX-14 隐私门禁的业务真实性清楚，视觉与拒绝反馈待验证

- 主层级：B。
- 页面/状态/证据：隐私门禁，E3/E4。
- 观察：门禁明确只保存必要本地偏好且不连接后端；拒绝仅显示 SnackBar。
- 用户影响：主信息可信，但大字号、长法务名称和读屏下的拒绝结果尚未证明。
- 行业惯例：同意必须知情，拒绝结果清楚，所有内容在短屏/大字号下可达，E1/E5。
- Admin9 推荐：保留专用品牌门禁模式；迁移时验证滚动、法务返回和平台反馈，不套普通 AppPage。
- 严重度：P2。
- 处理阶段：迁移阶段处理。
- 影响：页面结构特例是；公共 API 仅通用按钮/反馈；Token 可能。
- 验收：最大字号、短屏、VoiceOver/TalkBack 完整阅读、拒绝和再同意任务。

### UX-15 首页的“暂无内容”没有区分骨架空状态与派生业务空状态

- 主层级：B。
- 页面/状态/证据：首页，E3/E4。
- 观察：品牌图标与“暂无内容”说明当前没有内容，但没有下一步。
- 用户影响：作为骨架可接受，派生项目若原样保留会显得无目的。
- 行业惯例：空状态说明对象，并仅在存在真实下一步时给行动，E5。
- Admin9 推荐：保留为骨架占位证据，不纳入公共 Empty 组件；派生项目必须替换为自己的首页任务或真实空状态。
- 严重度：P3。
- 处理阶段：当前不处理；派生项目迁移时处理。
- 影响：公共 API/Token/通用页面结构否。
- 验收：基础仓库文档明确占位性质；派生项目发布门禁搜索“暂无内容”。

### UX-16 法务、关于和联系方式的占位边界真实但偏工程化

- 主层级：B。
- 页面/状态/证据：法务、关于、联系方式，E3。
- 观察：正式内容缺失时显示资源标识或“尚未提供”；版本信息可见。
- 用户影响：不伪造内容，但普通用户不需要资源标识，且无法采取下一步。
- 行业惯例：缺失内容使用面向用户的可用性说明，内部资源键用于日志而非主界面，E5。
- Admin9 推荐：骨架继续标记缺失但在参考基线中禁止把资源键当产品文案；派生项目发布前必须提供正式内容和联系方式。
- 严重度：P2。
- 处理阶段：迁移/派生发布阶段处理。
- 影响：页面内容是；公共 API/Token 否。
- 验收：发布清单验证两份法务正文、联系方式和版本来源，不出现内部资源键。

### UX-17 响应式和大字号缺少可执行页面证据

- 主层级：E。
- 页面/状态/证据：全部页面；当前 maxWidth 720、无宽度矩阵，E3。
- 观察：部分页面可滚动，但个人中心按钮行、设置尾部控件、资料页 Column 和注销表单没有 320/360/390/600 及横屏证据。
- 用户影响：窄屏、分屏或大字号下可能溢出、遮挡或丢操作入口。
- 行业惯例：按可用约束而非设备类型布局，保持状态和多输入可达，E1。
- Admin9 推荐：Phase 0C 同时产出标准/大字号结构规则；实现后固定宽度矩阵和手机横屏 Widget 测试。
- 严重度：P1。
- 处理阶段：参考页面阶段定义，组件/迁移阶段验证。
- 影响：页面结构是；Token 可能；公共 API 可能。
- 验收：320/360/390/600 与横屏无 overflow、裁切、遮挡或入口丢失。

### UX-18 反馈仍依赖 Material SnackBar 且没有公告证据

- 主层级：D。
- 页面/状态/证据：隐私拒绝、游客退出；E3。

- 用户影响：iOS 体验突兀，读屏用户可能错过结果。
- 行业惯例：非阻塞反馈遵循平台容器并保留消息、操作、关闭和读屏语义，E1/E5。
- Admin9 推荐：保留原 Phase 0 对反馈生命周期的产品语义，等参考页确认位置后进入 v1.2；页面不得自行选择反馈容器。
- 严重度：P2。
- 处理阶段：组件阶段处理。
- 影响：公共 API 是；Token 是；页面结构否。

### UX-19 灰度与高对比度截图不能证明可辨识性

- 主层级：E。

- Admin9 推荐：不把现有截图判为无障碍通过；参考页明确非颜色状态，组件阶段计算对比度。

- 处理阶段：参考页面阶段定义，组件阶段验证。

### UX-20 未知路由页缺少恢复路径

- 主层级：B。
- 页面/状态/证据：`_UnknownRoutePage`，E3。
- 观察：显示 routeName，但只依赖系统返回。
- 用户影响：深链或异常导航时用户可能不知道如何回到安全入口，原始路由名也偏工程化。
- 行业惯例：错误页说明发生了什么并提供可恢复行动，E5。
- Admin9 推荐：保留为开发边界；若派生项目开放深链，迁移时提供返回首页，不向普通用户显示原始 routeName。
- 严重度：P3。
- 处理阶段：迁移阶段按真实深链能力处理。
- 影响：页面结构是；公共 API/Token 否。
- 验收：有深链时从无效路径可回首页且不泄露内部 route；无深链时维持开发用途。

## 4. 两项侧边观察的最终收口

### 4.1 注册页比例

最终分类为 C 层的“表单节奏/控件密度待验证信号”，严重度 Unknown。它不构成等高要求，也不直接构成 P1。Phase 0C 必须用同一设备、明确字号和逻辑尺寸的双端样例，分别测量视觉 bounds 与 hit bounds；只有用户接受参考页且无障碍门禁通过后，才能把度量写入 Token。

### 4.2 个人中心布局

最终分类为 A 层信息架构问题，P1。它涉及身份呈现、游客/登录可用性、账号与应用入口分组、法务后置和危险操作隔离。`AppListTile`、`AppSection` 只负责渲染已确认结构，不能决定入口是否存在、顺序或权限状态。

后续参考设计必须回答：

1. 游客一眼能否识别当前状态和唯一主行动？
2. 哪些账号能力对游客真实可用？
3. 登录态显示哪些真实身份信息，缺失时如何降级？
4. 设置、法务、关于是否清晰后置且无重复入口？
5. 退出和注销是否只在适用状态出现并与普通入口隔离？
6. 大字号下身份摘要、按钮和分组是否保持阅读顺序？

## 5. 阶段汇合

可立即进入后续 v1.2 的结论：项目定位、页面只是能力样本、状态职责、平台自然目标、系统辅助设置合并、命中区/对比度门禁、按约束响应式、个人中心不由列表组件决定结构。

必须等待 Phase 0C 的结论：认证控件密度、具体间距和高度、个人中心最终分组视觉、设置行布局、按钮/输入/列表 Token、双端页面视觉映射。

## 6. Unknown 清单

- Android 所有页面视觉、edge-to-edge、IME、TalkBack、Switch Access、200% 字号和真机体验。
- iOS 最大 Dynamic Type、VoiceOver、Switch Control、Bold Text、系统高对比度和真实边缘返回取消/完成。
- 两张用户注册图对应的逻辑尺寸、App/系统字号、设备显示缩放和实际 hit bounds。
- 登录态真实身份内容、账号权限、法务正文、联系方式和后端完成结果。
- 320/360/390/600、横屏、键盘 traversal、Semantics 和对比度自动化结果。

Unknown 不阻止 Phase 0C 制作参考方案，但阻止把相关体验宣称为已通过或进入源码实施。
