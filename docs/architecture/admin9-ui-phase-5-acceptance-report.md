# Admin9 UI Phase 5 Acceptance Report

> **Historical record:** This report preserves its Foundation-era findings. It
> is not a current Starter specification or certification of any fork.

Status: Go for Phase 5 implementation; Phase 6 physical-device and human accessibility gates remain open

Date: 2026-07-29

## Scope

Phase 5 completes the frozen migration and cleanup boundary. All remaining
Foundation pages consume the public `App*` layer, the legacy widget wrappers and
legacy theme directory are removed, Gallery and representative Goldens are
complete, and the final import gate has an empty debt baseline. This phase does
not add a backend, fabricate a session, redesign a page, add a locale system, or
change the privacy, authentication, route, or `服务尚未接入` result.

## Migration and boundary result

- Home, Account guest/authenticated boundaries, Profile, account deletion, and
  Settings no longer choose Material/Cupertino interactive controls directly.
- `AppAppearanceController` exposes only semantic preferences through the public
  barrel. Effective system/App resolution and persistence remain internal host
  mechanisms.
- `foundation_page.dart`, `settings_section.dart`, and
  `unavailable_notice.dart` are deleted; no compatibility wrapper remains.
- The old `lib/core/theme/` location is deleted. Foundations now live under
  `lib/core/design_system/foundation/`.
- The final import-debt baseline is empty. The Phase 0D and final AST boundary
  modes, public export allowlist, Brand entry, positive fixtures, and all 19
  negative fixtures pass.
- Account identity artwork remains a feature-local page exception and is
  excluded from duplicate screen-reader speech. It does not enter Core.

## A-L and visual evidence

The canonical A-L matrix runs real Account, registration, and Settings pages at
320/360/390/600 logical widths, phone landscape, light/dark, standard/high
contrast, App 1.00/1.12/1.24, and deterministic system 1.0/2.0/3.0 scalers.
Required stresses explicitly cover long-label/trailing-value reflow, disclosure
and action reachability, error growth, disabled state, selected semantics, exact
E calibration, dark Extra Large F, max width, non-color state expression,
external-keyboard focus visibility, 300 logical-pixel IME inset, first-error
focus, scroll endpoint, and uncapped 2.0/3.0 composition.

`AppGalleryPage` supplies real A/F/G/L images plus real AppPage,
AppSingleChoiceList, feedback, action-menu, and iOS dialog states. The L run
found and closed an iOS `CupertinoTabBar` overflow: its height now grows from
the current `TextScaler` result while retaining the 50pt platform minimum and no
maximum cap or forced shrink.

## Review closure

Independent Flutter architecture, cross-platform UI, iOS HIG, and
accessibility/test reviews were run against the shared Phase 5 worktree. The
following contract-relevant findings were closed.

| Severity | Finding | Resolution |
| --- | --- | --- |
| P1 | page A-L test did not execute row-specific stresses | real-page assertions now cover every required stress, including IME and keyboard focus |
| P1 | Gallery A/F/G/L and critical public structures used only a custom fixture | actual Gallery state Goldens cover A/F/G/L, AppPage, single choice, feedback, menu, and dialog |
| P1 | iOS bottom navigation overflowed at system 3.0 x App 1.24 | TextScaler-driven content height with 50pt minimum; L and Phase 2 matrices pass |
| P2 | E/F page-pattern calibration was not directly reproducible | dedicated registration E and dark Settings F Goldens added |

No independent review left an open Phase 5 P0-P2 after the final re-review.
The CJK subset generation command/version/Unicode inventory is a documentation
P3 backlog and does not alter the committed font hash or runtime behavior.

## Decision

All Phase 5 migration, cleanup, Gallery/Golden, public-export, import-boundary,
accessibility, regression, and stage-acceptance P0-P2 findings are closed.
Automated and currently executable simulator gates pass. Phase 5 is `Go` and
may be committed. Phase 6 may execute delivery verification but must remain
blocked if its physical-device or human-operated hard evidence cannot be
obtained; code, Widget tests, simulators, and documentation cannot substitute
for those gates.
