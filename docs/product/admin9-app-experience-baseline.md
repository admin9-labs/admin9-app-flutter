# Admin9 App Foundation 产品体验基线

> 版本：Phase 0A
> 日期：2026-07-29
> 状态：已通过 Phase 0A/0B 验收；用于指导 Phase 0C，不直接授权源码实施

## 1. 文档目的

本文固定 Admin9 App Foundation 的产品角色、体验原则、信息层级、页面模式和治理方式。它回答“通用 App 骨架应该让人感受到什么、如何判断体验是否成立”，不定义 Flutter 公共 API、Token 数值或组件实现。

当前仓库中的页面只证明宿主边界和关键流程能够存在，不是获批的最终产品页面。现状代码、截图和 Flutter 默认样式都不能自动升级为正式设计规范。

## 2. 证据语言

本文及后续审计统一使用以下等级，避免把官方默认值、行业建议和个人感觉混在一起：

| 等级 | 含义 | 使用规则 |
| --- | --- | --- |
| `N` 规范门禁 | Admin9 为保障可访问性、平台完整性和业务真实性而设定的必须通过项；依据来自官方规范或明确产品边界 | 未通过即不能发布相关能力 |
| `D` 官方默认 | Flutter、Material 或 Cupertino 在当前 SDK 中的默认行为或数值 | 是起点，不等于 Admin9 最终视觉决策 |
| `R` 产品推荐 | 基于 Admin9 定位作出的唯一产品/UX判断 | 参考页面通过后进入正式基线 |
| `O` 观察证据 | 源码、截图、设备或用户原话反映的现状 | 只能触发诊断，不能直接成为实现要求 |
| `U` Unknown | 当前缺少设备、状态或设计样例，无法确认 | 必须写明补证路径，不得伪造结论 |

“硬规范”在本文仅指 Admin9 验收必须项，不暗示法律结论。Flutter 官方默认值与 Apple/Android 官方建议均要单独标记，不能互相替代。

## 3. 产品角色

### 3.1 服务对象与任务

Admin9 App Foundation 是仅面向 Android/iOS 派生项目的通用 Flutter App 基础骨架。它为后续业务 App 提供：

- 稳定的应用宿主、启动和生命周期边界。
- 首次隐私门禁与必要本地偏好。
- 一级导航和通用页面容器。
- 游客、认证入口和账号能力边界。
- 外观、字号与辅助功能设置入口。
- 用户协议、隐私政策、关于和联系方式承载位。
- 可由派生项目接入的通用体验规则与验收方法。

### 3.2 明确不解决

基础骨架不预设客户业务，不连接后端，不伪造用户、会话、成功结果或正式法务内容。它不是手机后台、运营控制台、展示型模板、营销站点，也不是 Material 3 组件示例项目。

“未接入”必须以真实边界呈现。派生项目接入真实服务后，才可以用真实成功、加载、错误和账号状态替换占位边界。

### 3.3 公共层与派生项目

| Admin9 公共层负责 | 派生项目负责 |
| --- | --- |
| 页面模式、交互语义、平台行为、无障碍底线、稳定状态表达 | 客户品牌资产、业务信息架构、真实字段、业务规则、接口与数据 |
| 通用视觉语义与可复用控件能力 | 页面内容优先级、业务文案、业务权限和危险操作条件 |
| 统一的测试入口和验收证据格式 | 在真实业务、设备和内容下完成验收 |

公共层不得读取业务 ViewModel、业务实体或服务。派生页面不得用局部样式绕过已确认的交互语义和无障碍门禁。只有经过治理流程确认的真实差异才能形成页面特例。

## 4. 核心体验原则

偏离任一原则时，必须留下书面记录：观察、受影响任务、偏离理由、适用范围、责任人、验证证据和撤销条件。涉及业务真实性、危险操作或无障碍的偏离不得以视觉偏好批准。

| 原则 | 业务语言定义 | 可执行规则 | 正例 | 反例 | 验证方式 |
| --- | --- | --- | --- | --- | --- |
| 可靠 | 用户每次操作都能预期结果，应用不伪造能力、不丢状态、不误导 | 未接入能力明确说明；提交防重复；返回、重启和配置变化后状态符合契约；危险操作可识别且可撤回时提供撤回 | 注册校验通过后说明“服务未接入”，不创建会话 | 显示“注册成功”但没有账号服务 | Widget/integration 状态断言、重启测试、双端人工任务 |
| 克制 | 每屏只突出当前任务，骨架不抢占派生业务的表达空间 | 一屏最多一个主行动区域；低频说明后置；装饰不承担状态；不使用嵌套卡片和无意义大标题 | 注册页突出提交，返回登录为次操作 | 多个等权重实心按钮、功能说明占据首屏 | 参考页面层级评审、首屏扫描、长文案检查 |
| 高效 | 常用任务入口明确，步骤、滚动和重复输入不过量 | 高频入口靠前；同一目的入口不重复；键盘 next/done 连续；错误靠近字段并聚焦首错；设置即时生效 | 游客在身份摘要后直接看到登录/注册 | 登录入口在多个分组重复出现 | 任务步数、焦点路径、错误修正和返回状态测试 |
| 平台自然 | 品牌语义一致，导航、选择、返回、反馈和系统能力符合平台习惯 | Android 保留 Material 行为；iOS 使用 Cupertino/adaptive 行为；业务页不自行判断平台；系统返回、键盘、选择器和读屏按平台验证 | iOS 边缘返回可取消和完成，Android predictive back 有系统证据 | iOS 页面只是 Material 控件换色 | 双端参考稿、组件映射测试、模拟器/真机手势验收 |
| 可扩展 | 派生项目能替换内容和接入能力，不需要复制或破解公共层 | 页面模式固定职责但不做任意 DSL；公共层接收语义数据；业务状态由 feature 持有；第二个真实消费者出现后才扩大公共 API | 派生项目传入真实法务内容和账号状态 | 公共组件内置“服务未接入”业务文案 | 导入边界检查、消费者盘点、API 变更评审 |
| 无障碍 | 不依赖单一感官或精细动作，系统设置和辅助技术可完成核心任务 | Android 触控目标至少 48x48dp；iOS hit region 至少 44x44pt；普通文字对比度至少 4.5:1，大字和关键非文字边界至少 3:1；支持系统字号、读屏、键盘和减少动态效果 | 图标按钮视觉可小，但命中区、名称、角色与状态完整 | 只靠红色表示错误，或放大后按钮文字被截断 | Semantics/尺寸/对比度自动化，加 VoiceOver/TalkBack 与键盘人工验收 |

## 5. 产品信息层级

### 5.1 任务层级

1. 页面主任务放在内容流中最易扫描的位置，一屏只设一个主行动区域。
2. 次要任务使用较低视觉权重，不能与主任务争夺注意力。
3. 危险操作与日常能力分组隔离，使用明确动词和危险语义；不得把危险操作标成默认主行动。
4. 页面标题说明当前位置，不能代替主任务描述。
5. 导航入口只表达去向；立即执行的动作必须以动作控件和结果反馈表达。

### 5.2 身份呈现

- 游客态先说明“当前没有用户会话”，再提供登录和注册；不得伪装头像、昵称或会员等级。
- 登录态展示派生项目提供的真实身份摘要；缺失字段显示中性缺省，不推断用户信息。
- 账号资料、安全、找回只属于账号能力；设置、法务和关于属于应用能力。
- 退出登录只在真实会话存在时成为可执行危险操作；游客态不显示可执行退出入口。

### 5.3 入口排序与隔离

固定顺序为：身份摘要与主行动 → 高频账号能力 → 应用设置 → 法务与关于 → 危险操作。派生业务可在身份与应用设置之间加入真实高频业务分组，但不得打散法务和危险操作边界。

同一页面不保留指向相同结果的重复入口。低频说明和版本信息不占用首屏主行动区域。

### 5.4 状态职责

| 状态 | 唯一职责 | 不得承担 |
| --- | --- | --- |
| 空状态 | 说明当前没有内容，并在存在真实下一步时提供行动 | 代替错误、未接入或加载 |
| 未接入 | 明确能力存在于骨架但当前没有服务，保持业务真实性 | 伪装成功或归因给用户 |
| 加载 | 表明系统正在处理且防止重复提交 | 无限等待、遮蔽取消路径 |
| 错误 | 说明发生了什么、用户能否修正、下一步是什么 | 仅显示错误颜色或内部异常 |
| 成功 | 确认已真实完成并说明后续状态 | 在没有后端或持久结果时出现 |

### 5.5 文案与操作

- 使用简短、具体、可验证的中文；按钮以动词或“动词+对象”命名。
- 主按钮描述提交后的真实动作，例如“提交注册”；不能写泛化的“确定”。
- 取消保持当前数据和上级状态，确认执行已说明的动作。
- destructive 确认必须点名对象与后果；取消始终可识别。
- 错误文案不责备用户，不泄露内部实现；未接入文案明确是当前版本边界。

## 6. 页面模式

页面模式只固定职责和体验边界，不生成任意页面 DSL。派生项目仍以普通 Flutter 页面组合内容。

| 页面模式 | 适用范围与层级 | 主次操作 | 滚动、安全区与大字号 | 平台差异 |
| --- | --- | --- | --- | --- |
| App Shell / 一级导航 | 2-5 个稳定、同级、高频目的地；当前固定首页和我的 | 切换目的地，不直接执行业务动作；重复点当前项由 Shell 处理 | 内容状态保留；系统栏、底栏和 IME 不遮挡；标签放大后不截断 | Android 使用 Material 导航行为；iOS 使用原生 Tab bar 语义与安全区 |
| 个人中心 | 身份摘要、账号能力、应用能力、法务/关于、危险操作 | 游客主行动为登录，注册为次行动；登录态无伪造动作 | 整页可滚动；分组标题不脱离内容；大字号时身份摘要和双按钮允许纵向重排 | iOS/Android 保持信息架构一致，列表、图标、返回和反馈遵循平台 |
| 认证表单 | 登录、注册、找回、重置、改密；每页只完成一种认证任务 | 提交为唯一主行动，流程切换为次行动 | 键盘出现时字段与提交可达；错误增加高度；大字号内容驱动增长，不固定控件高度 | 输入、密码可见性、返回、自动填充和选择行为使用平台能力 |
| 设置列表 | 可即时生效且可解释的本地偏好 | 行内控件改变单一设置；无需额外保存按钮 | 分组滚动；当前值可读；长标签和大字号时尾部控件不得挤压标题 | Android/iOS 使用各自 switch、segmented/select 表达，状态语义一致 |
| 普通列表与详情 | 可扫描入口列表、法务文本、关于和联系方式 | 列表项导航，详情页提供必要页面级动作 | 列表可滚动；详情长文可选择；内容宽度受约束但不按设备类型分支 | 顶栏、返回、分隔与披露指示遵循平台 |
| 隐私门禁 | 首次进入前说明必要本地处理和法务入口 | 同意并继续为主行动；暂不同意不进入应用 | 短屏和大字号可完整滚动；法务页面可返回门禁 | 保持品牌结构，返回和按钮反馈遵循平台；不强行套普通标题页 |
| 空、错误、不可用 | 页面或局部状态的明确占位 | 只在存在真实下一步时显示行动 | 文案不被裁切，图标不重复朗读，状态变化可公告 | 反馈容器遵循平台，语义和业务含义一致 |

## 7. 视觉与平台策略

### 7.1 三类决策所有权

| 决策层 | 固定内容 |
| --- | --- |
| 产品体验基线 | 页面任务、信息层级、状态含义、主次/危险操作、平台行为目标、无障碍门禁 |
| Design System / Token | 品牌色角色、字体层级、间距刻度、圆角、motion、组件状态和平台度量映射 |
| 页面特例 | 隐私门禁品牌结构、派生业务专属摘要、特殊法律或业务内容；必须有真实任务理由 |

品牌语义统一，平台行为原生。相同 tone、任务层级和状态在两端含义一致；控件外观、返回、选择、弹窗和反馈允许按平台实现。

### 7.2 “舒服”的判定

“舒服”必须同时具备三类证据：

1. 可量化规则：命中区、对比度、无裁切、焦点顺序、任务步数和状态保持。
2. 本文体验原则：层级克制、业务真实、平台自然。
3. 经用户接受的参考页面：个人中心、认证表单、设置页在标准和大字号下的双端样例。

缺少任一类证据时，只能记录观察或 Unknown，不能冻结为公共样式。

### 7.3 视觉容器与点击区域

视觉容器尺寸不等于命中区域。Flutter 3.44.1 的 Material 3 `FilledButton` 默认视觉最小尺寸为 64x40 logical pixels，而默认 `MaterialTapTargetSize.padded` 将相关 Material 控件的命中目标扩展到至少 48x48。Apple HIG 要求按钮 hit region 至少 44x44pt。

因此 Admin9 不要求按钮与输入框等高。参考页面需要同时检查视觉节奏和实际 hit target，不能通过压缩视觉高度破坏可访问性。

### 7.4 尺寸与大字号

- 当前阶段不冻结按钮、输入框、列表行的统一固定高度。
- 组件阶段使用 minimum constraints 保证平台命中区，内容、错误、辅助文字和系统字号可以驱动高度增长。
- 不以缩小文字、截断标签或覆盖系统字号换取整齐。
- 响应式依据可用窗口/父约束，不依据“手机/平板”硬编码。
- Phase 0C 必须在标准字号和大字号样例中校准表单节奏，再决定哪些度量进入 Token。

## 8. 治理流程

以后用户提交“这里不舒服”等观察时，固定按以下顺序处理：

`观察原文 → 专业诊断 → 行业惯例 → Admin9 唯一推荐 → 严重度 → 处理阶段 → 验收证据`

规则如下：

1. 保留观察原文和截图，不先改写成缺陷。
2. 诊断必须落入产品/信息架构、页面模式、Design System、平台行为、无障碍实现或主观假设中的一个主层级。
3. 明确证据是 `N/D/R/O/U` 哪一类。
4. 主任务给出唯一推荐；只有真实业务边界或两种方案都成立且代价不同，才请求用户决策。
5. 只有用户接受或规范门禁直接要求的结论，才能进入正式体验基线、参考页面或 v1.2。
6. Token、组件 API、测试方法和专业验收细节由产品/设计/工程负责人承担，不转交给用户。

## 9. 对 v1.2 的输入边界

Phase 0A 验收后可直接进入 v1.2 的内容：产品定位、公共层/派生项目边界、状态职责、平台自然原则、命中区与对比度门禁、响应式依据、治理流程。

必须等待 Phase 0C 参考页面获批后才能进入 v1.2 的内容：按钮/输入框/列表密度、页面间距、个人中心分组细节、认证表单节奏、设置行布局、具体视觉层级和由这些样例推导的 Token。

## 10. 官方来源

- Flutter, [General approach to adaptive apps](https://docs.flutter.dev/ui/adaptive-responsive/general)：按可用窗口/父约束测量，不按硬件类型判断；全局与局部布局分别使用 `MediaQuery.sizeOf` 和 `LayoutBuilder`。
- Flutter, [Best practices for adaptive design](https://docs.flutter.dev/ui/adaptive-responsive/best-practices)：优先触控体验、保留状态、支持多种输入，避免锁定方向和吞满大屏宽度。
- Flutter, [User input & accessibility](https://docs.flutter.dev/ui/adaptive-responsive/input)：内建控件的焦点/键盘能力、自定义控件的 traversal 与 focus 要求。
- Flutter API, [MaterialTapTargetSize](https://api.flutter.dev/flutter/material/MaterialTapTargetSize.html)：`padded` 默认扩展到 48x48。
- Flutter API, [FilledButton.defaultStyleOf](https://api.flutter.dev/flutter/material/FilledButton/defaultStyleOf.html)：Material 3 默认 `minimumSize` 为 64x40，并随文字缩放调整 padding。
- Android Developers, [Make apps more accessible](https://developer.android.com/guide/topics/ui/accessibility/apps)：48x48dp 触控目标及 4.5:1/3:1 对比度建议。
- Apple HIG, [Buttons](https://developer.apple.com/design/human-interface-guidelines/buttons)：至少 44x44pt hit region、主次/危险角色和清晰动作标签。
- Apple HIG, [Accessibility](https://developer.apple.com/design/human-interface-guidelines/accessibility)：系统辅助能力、非颜色单一表达和包容性设计原则。

来源回读日期为 2026-07-29。官方默认值在 Flutter 升级后必须重新核对。
