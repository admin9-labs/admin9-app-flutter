## Reproduction

Run the source gates documented in [AGENTS.md](../../AGENTS.md), then use:

```sh
python3 tool/run_starter_device_acceptance.py android \
  --device ANDROID_SERIAL --output build/ui_evidence/starter/android
python3 tool/run_starter_device_acceptance.py ios \
  --device IOS_UDID --output build/ui_evidence/starter/ios
```

The host script backgrounds Android using the Home key, or activates iOS Settings,
then returns to Starter. It waits for the test's explicit readiness marker.
Device authorization, developer signing and any vendor install confirmation
must already be available. When connecting to an already installed Android test
binary, `flutter drive --use-existing-app=<VM-service-URL>` can run the same driver;
the host must still react to the readiness marker with the same OS actions.
Without `STARTER_OS_LIFECYCLE=true`, the integration test injects lifecycle
notifications and does not claim OS lifecycle acceptance.

The test-only transport loads licensed bundled media through the real validation,
cache and renderer. The normal build has no placement endpoint and disables ads.
No test-only advertising activation was added to production.
