# Admin9 Phase 0C Gate 1 设计决策

> 日期：2026-07-29
> 状态：待用户结构验收
> 范围：三张参考页的 Android/iOS 低保真结构，不是视觉规范、组件 API 或源码实现

## 1. 唯一设计方向

Admin9 App Foundation 采用克制、安静、偏生产力工具的通用 App 基底。结构稿使用中性背景和表面、一个蓝色标注色及独立危险语义色，只帮助识别层级和状态；颜色、字号、间距、圆角、阴影和高度均未冻结为 Token。

固定规则：

- 不使用营销式大标题、渐变、装饰性卡片、嵌套卡片或组件展示页构图。
- 信息顺序、tone、主次/危险操作和业务真实性跨平台一致。
- Android 保留 Material 3 的导航、反馈、输入、选择和返回预期。
- iOS 使用 Cupertino 导航、分组列表、披露、开关、选择反馈和边缘返回预期。
- 平台系统字体作为默认基线；大字号重新排版，不整体缩放标准稿。
- 点击区域与视觉容器分开标注；绿色虚线表示 hit bounds，实线表示 visual bounds。
- 按钮与输入框不强制等高；错误、说明和系统字号可以推动内容增长。

## 2. Gate 1 资产解释

每张页面资产包含三个 390 logical pixels 结构画布，并以 78% 比例放入 1800x1120px 的审阅板：

| 页面 | 画布一 | 画布二 | 画布三 |
| --- | --- | --- | --- |
| 个人中心 | 标准字号游客态 | 标准字号登录态 | 大字号身份字段缺失态的滚动终态，证明危险区仍可达 |
| 认证表单 | 注册标准字号键盘打开态 | 注册大字号字段错误态 | 登录服务未接入对照态 |
| 设置 | 标准字号当前值 | 大字号系统强制开启/App 偏好关闭态 | 平台单选页 |

画布内部坐标使用 logical pixels；审阅板像素只影响文档展示比例，不代表设备截图。每张 PNG 顶部都标注平台、逻辑宽度、字号和状态，右上角明确写明“非当前 App 截图 / 非设备证据”。

## 3. 跨平台统一与差异

| 任务 | 跨平台统一语义 | Android 固定结构 | iOS 固定结构 |
| --- | --- | --- | --- |
| 一级导航 | 首页、我的同级且保持状态 | Material NavigationBar 预期 | Cupertino Tab bar 预期 |
| 二级页返回 | 返回上级并保持约定状态 | 系统 back / predictive back 预期 | 导航返回 / 边缘返回预期 |
| 个人中心目录 | 身份、账号、应用、法务、危险边界顺序一致 | Material 列表与反馈 | Cupertino 分组列表与披露 |
| 表单 | 字段、错误、主次行动、未接入语义一致 | Material 输入与按钮反馈 | Cupertino/adaptive 输入与按钮反馈 |
| 主题/字号选择 | 单选立即生效并停留；用户返回后主列表显示当前值 | Material 单选列表 | checkmark 单选列表及 selected trait |
| 布尔设置 | 行内切换、状态可读、无需保存 | Material Switch | CupertinoSwitch |

首版主题和字号不使用 segmented control 或下拉框。平台差异不得改变入口权限、校验规则、状态职责或危险操作后果。

## 4. 页面结构决策

### 4.1 个人中心

固定顺序为：身份摘要与主行动 → 账号能力 → 应用设置 → 法务与关于 → 危险操作。

- 游客只显示当前未登录、登录、注册、账号找回、设置、法务与关于。
- 游客不显示资料、改密、退出或注销，不保留点击后必然失败的日常入口。
- 登录态显示派生项目提供的真实身份摘要、账号资料和账号安全，不重复登录或注册；结构稿中的身份明确标为示例。
- 身份字段缺失时使用“昵称未提供”等中性缺省，不猜测数据。
- 退出登录位于独立危险边界；账号注销仍保留在账号安全流程。
- 联系方式只从关于进入。
- 身份摘要、游客行动区和危险区属于页面特例，不由列表组件决定。

### 4.2 认证表单

- 注册是主样例：账号、新密码、确认密码；登录是账号、密码的独立对照。
- 标签持续可见；placeholder 不独自承担字段名称。
- 错误紧邻字段并推动布局增长；提交后焦点移动到首个错误字段。
- 键盘顺序为 next，注册最后字段为 done；done 触发本地校验。
- 密码可见性具备独立名称、状态和 48x48 logical pixels 的结构 hit bounds。
- 提交注册/登录是唯一主行动；返回登录、注册和找回均为次操作。
- 校验通过只显示“当前版本服务未接入”，不使用成功 tone、不清空输入、不创建会话。
- 提交中只预留防重复提交结构，不模拟网络等待。
- 输入保留范围固定为当前认证路由：本地校验、修错、未接入结果和 iOS 边缘返回取消期间保留；路由完成 `pop` 或登录/注册流程替换后清除。该规则不承诺跨路由恢复草稿。

### 4.3 设置

- 外观固定包含主题、App 字号；辅助功能固定包含灰度、高对比度、减少动态效果。
- 主题和字号进入平台单选页；返回后主列表显示当前值。
- 单选立即生效但页面不自动返回；用户通过平台返回比较并确认选择。
- 布尔项在当前行即时切换，不设置保存按钮。
- 有效状态由系统要求与 App 偏好合并，App 偏好不得削弱系统要求。
- 系统强制开启而 App 偏好关闭时，开关只表达 App 偏好，邻近文字说明系统要求和最终有效状态。
- 大字号下标签优先换行，当前值进入次行；开关和披露保持完整点击区域。

### 4.4 系统要求与 App 偏好合并

| 设置 | 持久化的 App 值 | 系统输入 | 唯一有效规则 |
| --- | --- | --- | --- |
| 主题 | 跟随系统、浅色、深色 | 系统亮/暗模式 | 跟随系统时取系统值；显式浅色/深色取 App 值。主题不是辅助功能强制项 |
| App 字号 | 标准、大号、特大 | 系统非线性 `TextScaler` | 标准等同系统结果；大号、特大只能在系统结果上单调放大，不设置低于系统结果的总上限。具体倍率等待视觉校准，不在 Gate 1 冻结 |
| 灰度 | 开/关 | 操作系统自身的显示调节 | App 只控制自身灰度滤镜；系统显示调节由系统所有，App 不检测、不抵消 |
| 高对比度 | 开/关 | 系统 `highContrast` | 最终有效值为 `systemHighContrast OR appPreference`；只持久化 App 偏好 |
| 减少动态效果 | 开/关 | 系统 `disableAnimations` | 最终有效值为 `systemDisableAnimations OR appPreference`；保留平台导航/返回手势 Builder，只减少非导航动画与转场视觉运动 |

系统要求是瞬时只读输入，App 偏好是唯一持久化输入，最终有效状态由单一 appearance owner 派生。系统状态变化时重新派生并公告最终状态；不得把最终状态回写成 App 偏好。

## 5. 量化结构门禁

| 项目 | Gate 1 规则 | 当前结构证据 |
| --- | --- | --- |
| Android hit target | 不小于 48x48dp | 主按钮、返回、密码图标、文字次操作、列表行和开关虚线结构均不小于 48 logical pixels |
| iOS hit region | 不小于 44x44pt | 当前主按钮、返回、密码图标、文字次操作和尾部控件统一采用不小于 48 logical pixels 的交互结构 |
| 主行动 | 一屏最多一个主行动区域 | 游客登录、注册提交、登录提交各自唯一；设置没有保存按钮 |
| 错误增长 | 错误不得覆盖后续内容 | 错误位于字段下方并增加字段块高度 |
| 尾部内容 | 不挤压主标签 | 大字号时当前值进入次行；开关/披露保留独立区域 |
| 状态表达 | 不只依赖颜色 | 错误、未接入、选择和开关均有文字、形状或状态标识 |
| 对比度目标 | 普通文字 4.5:1；大字/关键边界 3:1 | 仅记录后续视觉验收目标；低保真未宣称实测通过 |

## 6. 响应式策略

- 320/360：保持单列，水平边距按可用空间收缩；双行动改为纵向；列表尾部内容必要时进入次行。
- 390：作为 Gate 1 主画布，结构如标注 PNG。
- 600：内容区域限宽并居中，增加外侧留白，不把手机结构横向拉满。
- 手机横屏：保持单列和整页滚动；键盘出现时当前字段、错误和主行动可滚动到可见区域。
- 大字号：内容驱动增高；不缩小文字、不裁切标签、不覆盖系统 TextScaler。

上述是重排规则，不是按设备型号分支。实现后仍须用 320/360/390/600 与横屏 Widget 窗口验证。

## 7. 焦点、读屏和状态变化

| 页面 | 预期顺序 |
| --- | --- |
| 个人中心 | 页面标题 → 身份摘要 → 主/次行动 → 账号 → 应用 → 法务与关于 → 危险操作 → 一级导航 |
| 认证表单 | 返回我的（button role、hit bounds）→ 页面标题 → 说明 → 字段/字段错误 → 主行动 → 未接入结果 → 次操作 |
| 设置 | 主设置页为返回我的；选择页为返回设置；随后页面标题 → 分组 → 标签/说明 → 当前值或开关状态 → 下一项 |

路由进入后先公告页面标题，不强制把键盘焦点移入内容；后续 swipe/tab 遍历按上表的视觉顺序执行。表单提交失败时例外：焦点移到首个错误字段并只公告一次错误。iOS 单选项朗读“选项名 + 已选/未选”，当前项具备 selected trait；用户返回后焦点回触发行并公告新当前值。反馈不得把焦点从正在修正的字段无理由移走。当前为结构预期，VoiceOver/TalkBack 设备结果仍为 Unknown。

## 9. Unknown 与停止边界

- Android/iOS 真机视觉、读屏、系统返回、手势、IME 和键盘结果均未执行。
- 低保真颜色没有作为最终颜色进行对比度实测。
- 标准/大字号的最终字体、间距、圆角、阴影和视觉高度尚未校准。
- 登录态真实身份字段、派生项目业务入口、法务正文和服务结果尚不存在。
- 两张注册截图对应的逻辑尺寸、系统/App 字号、显示缩放和实际 hit bounds 未知。

## 10. Gate 1 与 Phase 0C 最终门禁

| 范围 | Gate 1 本轮 | Phase 0C 后续 |
| --- | --- | --- |
| 三页双端信息结构、平台控件映射、主次/危险操作 | 提交用户结构接受判断 | 保持已接受结构，不重新开放方向 |
| 390lp 浅色低保真、标准/大字号关键状态 | 本轮结构证据 | 扩展为获批视觉基准并实测 |
| 320/360/600、横屏 | 规则已固定，画布/实现证据 Unknown | 视觉阶段补结构资产；实现后补 Widget/设备证据 |
| 深色、灰度、高对比度、减少动态效果 | 状态与合并规则已固定，视觉证据 Unknown | 补完整双端视觉与对比度记录 |
| Token/API/固定高度 | 不冻结 | 仅三页共同证明且通过验收的规律可成为候选 |

本阶段路线在执行顺序上取代旧 Phase 0 报告第 11 节“下一步仅先修订 v1.2”的安排：用户接受 Gate 1 后仍继续 Phase 0C 视觉校准；Phase 0C 全部通过后才可另行授权 Phase 0D 修订 v1.2。该顺序不授权 Phase 1。

Gate 1 完成后停止。用户接受三页结构前，不制作完整深色/高保真视觉稿，不修订 v1.2，不创建 Token/API，不进入 Phase 0D 或 Phase 1。
