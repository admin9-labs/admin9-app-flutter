# Admin9 参考页面设计任务书

> **历史记录：** 本文保留 Foundation 阶段的设计任务，不是当前 Starter 规范，也不
> 约束任何 fork。

> 阶段：Phase 0B
> 日期：2026-07-29
> 状态：已通过 Phase 0A/0B 验收；仅指导 Phase 0C 结构与视觉方案，不授权源码实现

## 1. 任务书目的

Phase 0C 只为个人中心、认证表单和设置页制作 Android/iOS 低保真与视觉参考。三张参考页用于校准页面层级、平台行为和视觉节奏，再反推 v1.2、Design System 与组件边界；它们不是派生项目的业务模板，也不生成任意页面 DSL。

设计输入固定为《Admin9 App Foundation 产品体验基线》和《Admin9 当前 UI/UX 审计》。当前 Material 页面只作为现状证据，不能作为视觉稿底版。所有样例继续遵守无后端、无真实会话、不伪造成功的产品边界。

## 2. 共用设计约束

### 2.1 必须同时提交的画面

每张参考页必须提供 Android 与 iOS 两套方案，并各自包含：

- 浅色、标准字号。
- 深色、标准字号。
- 浅色、大字号；内容按系统非线性缩放结果排版，不用整体等比放大截图代替。
- 关键错误、不可用、焦点、按下、禁用和读屏状态的标注稿。

个人中心另需游客态与登录态；认证表单另需初始、输入、字段错误、修正和服务未接入；设置页另需默认值与修改后状态。

### 2.2 固定体验规则

1. 一屏只有一个主行动区域。次操作降低视觉权重，危险操作独立分组。
2. 品牌语义、信息顺序和状态含义跨平台一致；导航、返回、输入、选择、开关、反馈和系统手势遵循各平台习惯。
3. 点击区域与视觉容器分别标注。Android 触控目标至少 48x48dp，iOS hit region 至少 44x44pt。
4. 控件采用最小约束并允许内容驱动增长。不得先规定按钮与输入框等高，不得用固定高度压制错误文案或大字号。
5. 响应式以可用约束为依据。低保真必须说明 320、360、390、600 logical pixels 和手机横屏下的重排规则。
6. 状态不能只靠颜色表达；普通文字对比度至少 4.5:1，大字和关键非文字边界至少 3:1。
7. 系统辅助设置优先，App 偏好只提供可解释的补充控制；两者合并后的有效状态必须能被用户和读屏识别。

### 2.3 不在本轮冻结的内容

- 按钮、输入框和列表行的固定高度。
- 最终间距、圆角、阴影、字号数值和组件 Token。
- 公共组件 API、Flutter 类型和内部组合方式。
- 忘记密码、重置密码、修改密码、找回、资料和注销的最终业务页面。

上述内容只有在三张参考页通过设计门禁后，才能按已出现的真实共性进入 Phase 0D；没有跨页面共性的内容保留为页面特例。

## 3. 参考页一：个人中心

### 3.1 页面目的与用户任务

个人中心让用户先确认当前身份，再进入当前状态下真实可用的账号或应用能力。它不是功能总目录，也不承载派生项目尚未定义的业务入口。

游客的首要任务是登录，注册是次要任务；登录用户的首要任务是确认身份并进入高频账号能力。设置、法务与关于后置，退出与注销只在真实会话存在时出现。

### 3.2 固定信息层级

| 顺序 | 游客态 | 登录态 |
| --- | --- | --- |
| 1 | “当前未登录”的身份摘要，不使用虚构头像或昵称 | 派生项目提供的真实身份摘要；缺失字段使用中性缺省 |
| 2 | 登录主行动、注册次行动 | 无重复登录/注册行动 |
| 3 | 账号找回 | 账号资料、账号安全 |
| 4 | 应用设置 | 应用设置 |
| 5 | 用户协议、隐私政策、关于 | 用户协议、隐私政策、关于 |
| 6 | 不显示退出、改密、资料和注销 | 独立危险区；退出在前，注销位于安全流程内 |

联系方式从“关于”进入，不在个人中心重复。基础骨架不预留空白业务分组；派生项目有真实高频任务时，新增分组位于账号能力与应用设置之间。

### 3.3 必须状态

- 游客态、登录态、身份字段缺失态。
- 标准字号和大字号下的首屏、完整滚动和返回位置。
- 列表项按下、键盘焦点、禁用状态；不存在不可解释的游客禁用账号入口。
- 登录态危险区在浅色、深色、灰度和高对比度下均不只依赖红色辨识。

### 3.4 Android 与 iOS 差异

- Android 使用 Material 页面栏、列表反馈、披露语义和系统返回预期；底部一级导航保持 Material 语义。
- iOS 使用 Cupertino 导航栏、列表分组、披露指示与边缘返回预期；一级导航保持 Tab bar 语义。
- 两端的信息顺序、入口可用性、主次关系和危险边界完全一致，不允许用平台差异改变产品权限。

### 3.5 大字号与页面特例

身份摘要允许增高，登录/注册横向空间不足时按阅读顺序改为纵向。分组标题不得与首个项目分离，尾部图标不得挤压主标签。页面特例仅包括身份摘要、游客行动区和登录态危险区；它们不下沉为 `AppListTile` 或 `AppSection` 的结构决策。

### 3.6 设计完成门禁

- 游客与登录两态均能在一次首屏扫描中识别身份、唯一主行动和首个可用能力。
- 游客态不存在必然失败的资料、改密、退出或注销入口；登录态不存在重复认证入口。
- 应用设置、法务/关于和危险操作形成清晰且固定的后置层级。
- 320/360/390/600、横屏和大字号重排规则无裁切、重叠或入口丢失。
- Android/iOS 的平台控件和返回预期已标注，点击区域和读屏名称可核验。
- 用户接受两端低保真和视觉参考；不接受时只回到本任务书定位问题，不修改源码。

## 4. 参考页二：认证表单

### 4.1 页面目的与用户任务

注册是主样例：用户按顺序填写账号、新密码、确认密码，修正本地错误后提交；当前版本只如实显示服务未接入，不创建会话。登录作为对照，用账号与密码验证相同页面模式是否支持不同任务，而不是设计一个万能表单。

### 4.2 固定信息层级与字段行为

1. 页面标题和一句必要说明先说明当前任务，不放营销内容。
2. 注册字段顺序固定为账号、新密码、确认密码；登录固定为账号、密码。
3. 标签持续可见，不用 placeholder 独自承担字段名称。密码可见性按钮具有名称、角色、当前状态和足够点击区域。
4. 键盘 action 按字段顺序使用 next，最后字段使用 done 并触发表单校验；焦点移动到首个错误字段。
5. 字段错误紧邻所属字段，错误出现后内容自然增高且不遮挡后续输入。
6. 注册页“提交注册”为唯一主行动，“返回登录”为次行动；登录页“登录”为唯一主行动，注册入口与找回入口均为次操作且不重复。
7. 本地校验通过后显示“当前版本服务未接入”的局部结果，不使用成功 tone、不清空输入、不创建会话。

### 4.3 必须状态

- 初始、逐字段输入、密码隐藏/显示、键盘打开。
- 空值、格式错误、密码不一致、首错聚焦。
- 修正后重新提交、服务未接入、返回后状态。
- 提交中与防重复提交的结构标注；当前无后端，不伪造网络 loading 时长。
- 标准字号、大字号、短屏、横屏、外接键盘焦点和读屏公告顺序。

### 4.4 Android 与 iOS 差异

- Android 采用 Material 输入、按钮、错误与系统返回行为，保持系统输入法和自动填充能力。
- iOS 采用 Cupertino/adaptive 的导航、输入反馈、按钮层级和边缘返回预期，键盘与密码能力遵循 iOS。
- 两端字段顺序、校验含义、主次行动和未接入结果一致。平台视觉差异不得改变账号规则。

### 4.5 表单节奏校准

Phase 0C 在同一逻辑窗口、明确系统字号和 App 字号的条件下记录：字段视觉 bounds、字段间距、错误后高度、主按钮视觉 bounds、主按钮 hit bounds、首屏可见范围和键盘遮挡。`registration_large.png` 与 `registration_standard.png` 只作为密度观察，不作为数值来源。

按钮不与输入框强制等高。设计必须同时证明主行动足够突出、视觉节奏克制、点击区域合规且大字号可增长，之后才能建议 Token 数值。

### 4.6 页面特例与设计完成门禁

页面特例仅包括认证任务说明、流程切换关系和服务未接入局部结果；字段容器、按钮和错误语义在出现跨页面共性后才进入公共组件。

设计完成必须同时满足：

- 注册与登录的字段、键盘、焦点、错误和返回关系均可沿任务图逐步核对。
- 服务未接入不被误认成错误或成功，输入和会话状态符合真实边界。
- 标准/大字号与 320/360/390/600、横屏、键盘打开状态均无裁切、遮挡和不可达操作。
- 点击区域、对比度、读屏名称/角色/状态和公告顺序有标注。
- Android/iOS 参考图通过用户接受判断，且没有从单张截图冻结等高或固定高度。

## 5. 参考页三：设置

### 5.1 页面目的与用户任务

设置页让用户查看并即时调整基础骨架负责的本地体验偏好：主题、App 字号、灰度、高对比度和减少动态效果。页面不设置保存按钮；每次更改立即生效并持久化，返回与重启后结果可预测。

### 5.2 固定信息层级

| 分组 | 顺序 | 表达 |
| --- | --- | --- |
| 外观 | 主题、App 字号 | 当前值始终可读；主题固定为跟随系统、浅色、深色；字号固定为标准、大号、特大 |
| 辅助功能 | 灰度、高对比度、减少动态效果 | 每行一个布尔状态；标签说明能力，不用颜色或图标独自表达开关结果 |

系统字号、系统高对比度和系统减少动态效果不复制成伪开关。参考稿必须标注系统设置与 App 偏好合并后的有效状态，并说明 App 选项不能削弱系统要求。

### 5.3 必须状态

- 系统默认、App 默认、每个选项改变后的即时状态。
- 浅色/深色、标准/大号/特大、灰度、高对比度、减少动态效果的可观察结果。
- 系统与 App 偏好同时存在时的有效状态说明。
- 长标签、大字号、尾部控件、键盘焦点、读屏开关状态和重启持久化。

### 5.4 固定平台映射

| 任务 | Android 参考 | iOS 参考 |
| --- | --- | --- |
| 页面导航 | Material top app bar 与系统返回 | Cupertino navigation bar 与边缘返回 |
| 主题三选一 | Material 单选列表 | iOS 单选列表，当前项使用 checkmark |
| 字号三选一 | Material 单选列表 | iOS 单选列表，当前项使用 checkmark |
| 布尔设置 | Material Switch | CupertinoSwitch |

首版不使用 segmented control 或下拉框承载主题与字号。选择页返回后，设置列表行显示当前值；布尔设置在当前行即时切换。此映射是 Phase 0C 的唯一设计输入，后续只有设备可用性证据才能申请调整。

### 5.5 大字号、页面特例与设计完成门禁

标题和说明优先换行，尾部当前值或开关保持完整命中区；空间不足时当前值进入第二行，阅读顺序保持“标签、说明、当前值/状态”。页面特例仅包括系统状态与 App 偏好合并的说明，不建立设置 DSL。

设计完成必须同时满足：

- 三选一与布尔项的平台映射明确，不存在开发者自由选择控件。
- 修改即时反映在页面与应用外观，返回和重启后结果与持久化契约一致。
- 灰度、高对比度和减少动态效果的状态不只靠颜色或动画判断。
- 320/360/390/600、横屏和大字号下标签、当前值、开关无重叠或裁切。
- VoiceOver/TalkBack 能读出标签、角色、当前值、状态变化，焦点顺序与视觉顺序一致。
- 用户接受 Android/iOS 低保真和视觉参考。

## 6. 完整参考任务

### 6.1 外观设置与持久化

固定任务路径：

`首页 → 我的 → 设置 → 修改主题 → 修改 App 字号 → 开启灰度 → 开启高对比度 → 开启减少动态效果 → 返回我的 → 切换首页 → 结束并重启 App → 回到设置确认持久化`

验收记录必须包含每一步的当前页面、选中状态、返回后页面位置、重启后有效值和 Android/iOS 差异。减少动态效果开启后仍需保留清晰的状态变化和平台返回能力，不能用“无动画”替代结果反馈。

### 6.2 注册错误修正与服务边界

固定任务路径：

`我的游客态 → 注册 → 输入不完整/不一致内容 → 提交 → 聚焦首错 → 修正 → 再提交 → 显示服务未接入 → 确认输入保留且无会话 → 返回登录 → 返回我的`

验收记录必须证明错误属于具体字段、读屏只公告必要变化、重复提交受控、未接入不显示成功、返回关系明确。当前阶段不模拟网络响应或账号创建。

## 7. Phase 0C 交付证据

每张参考页必须提交：

1. 标注信息顺序、主次/危险行动、滚动和重排规则的低保真稿。
2. Android/iOS 浅色、深色、标准字号和大字号视觉参考。
3. 关键状态标注与平台组件映射表。
4. 视觉 bounds、hit bounds、对比度和逻辑窗口尺寸记录。
5. 可供后续 Gallery 覆盖的状态矩阵；Gallery 只展示已批准组件，不代替页面任务验收。
6. 后续真机任务清单：Android TalkBack/返回/IME，iOS VoiceOver/边缘返回/键盘，以及双端大字号、灰度、高对比度和减少动态效果。
7. 用户对三张参考页分别给出的接受或不接受结论；不要求用户决定 Token、API 或测试实现。

Phase 0C 只有三张页面及两条完整任务全部通过上述门禁后才能结束。随后进入 Phase 0D，依据已批准证据修订 v1.2 并解决 declaration probe；仍不得直接进入 Phase 1。
